### 범위와 사용자 동작 계약

ISBN과 앱 DTO/오류 코드 유지. 매일 28권 1회 목록 요청 후 요일별 4권 캐시. 실패 시 이전 캐시 유지, 없으면 기존 오류. 기존 책의 ID/참조/제목/좋아요 보존. 상세 미등록/장애 시 DB fallback. API 키는 환경변수만 참조.

## 2. 변경 전

계정 공유 예산과 서버 간 추천 갱신 소유권 검증이 없었다. 소개는 VARCHAR(255)였으며 저장 무결성 오류를 중복 ISBN으로 취급할 여지가 있었다. 알라딘 임계값/응답에 의존한 구현으로 예스24 소개를 안전하게 보존하지 못했다.

## 3. 가설·근거·기대 결과

Redis Lua 원자 연산과 MySQL 기본키 충돌 처리를 사용하면 새 의존성 없이 여러 서버/동시 요청의 상태를 보존할 수 있다. 계정 간격/일일 예산 검증, 오래된 잠금 소유자의 쓰기 금지, 긴 소개 원문 저장, 동일 ISBN 재사용을 성공 조건으로 삼는다. 처리 속도 개선은 목표로 삼지 않는다.

## 4. 변경 후

- 공통 Redis TIME 기반 허용 간격/일일 예산/Retry-After cooldown, 1.5초 대기 상한. Redis 오류 시 외부 호출 중단.
- TTL 잠금과 소유권 검사 후 목록/날짜 원자 저장, KST 일관성, 기존 추천 fallback.
- LONGTEXT 확장과 INSERT ON DUPLICATE KEY UPDATE id=id. 외부 상세 ISBN 일치 확인, 다른 저장 오류 전파.
