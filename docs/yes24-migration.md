# 예스24 전환 진행 기록 (#309)

## 확정한 동작

- 기존처럼 매일 국내도서 종합 베스트셀러 28권을 목록 요청 한 번으로 조회한다. 요일에 해당하는 4권만 Redis에 저장·표시한다.
- 갱신 실패 시 이전 4권을 유지한다. 이전 캐시가 없으면 기존 오류를 반환한다. 주간 28권 고정 저장·추가 페이지 보충·신규 실패 UI는 도입하지 않는다.
- 검색은 `category=BOOK`, `sort=DEFAULT`. ISBN을 예스24 상품번호로 치환하지 않는다.
- 상세 조회 미등록·장애 시 기존 DB 정보를 제공한다. 저장된 책이 없으면 미등록(`BOOK_400`)과 장애(`BOOK_500`)를 구분한다.

## 단계별 상태

1. `0a459f56`: JSON DTO와 기존 converter 변환 추가. 신규 14개 + 기존 2개 변환 테스트 통과.
2. `f87afaab`: 검색·상세·추천의 실제 요청을 `Yes24Client`로 통합. 예스24 설정 프로필, 검색 404 변환, 상세 DB fallback 및 검색 캐시 공급자 구분 적용.

3. `08cc4ced`: 계정 공통 호출 제한·KST 일일 예산·429/503 cooldown. 인증 등 4xx 즉시 재시도 차단.
4. `5374c750`: 추천 공유 잠금, 소유권 검증 및 캐시 목록/날짜 원자적 저장.
5. `c77af584`: 긴 소개 LONGTEXT 확장, 동일 ISBN 동시 등록 보존, 저장 오류 전파.
6. 읽기 전용 데이터 점검 SQL 및 [운영 보존 절차](yes24-data-preservation.md) 추가. 실제 운영 데이터는 아직 점검하지 않았다.

## 2단계 구현 내용

- `application-yes24.yml`을 포함하고 `YES24_API_KEY` 환경변수를 참조한다. 기존 알라딘 키·XML 요청 설정은 사용하지 않는다. 실제 키를 파일에 저장하지 않았다.
- `detail=N` JSON 요청, `X-Api-Key` 헤더 인증, 검색어를 URI 변수로 인코딩한다. 검색은 기존 페이지 크기 10, 추천은 28로 요청한다.
- 검색 `404/SEARCH_001`만 성공 빈 목록으로 변환한다. 상세 `404/GOODS_001`, `GOODS_002`는 책 미발견이다. `SEARCH_002`, 알 수 없는 404, 인증·429·503은 공급자 오류로 유지한다.
- 예외에는 원본 응답 본문·요청 URI·인증 헤더·원본 cause를 넣지 않는다. HTTP 상태와 숫자형 Retry-After만 보존한다. 429/503 Retry-After는 계정 공통 cooldown에 반영한다.
- 상세 fallback은 기존 ISBN과 제목·저자·출판사·소개·표지 URL을 보존하고 link는 null로 반환한다. 현재 상세 API에는 회원 인수가 없으므로 likedByMe 기본 false 계약을 유지한다. 검색/추천 회원별 좋아요 계산은 기존 경로를 사용한다.
- 기존 `AladinApiService`, 검색/추천 wrapper 및 지표 이름은 단계 분리를 위해 임시 유지했다. 내부 HTTP 호출은 예스24로 변경했다. 외부 `BOOK_*` 오류 코드는 유지한다.

## 검증과 제한

- HEAD를 임시 폴더로 내보낸 뒤 이번 변경만 복사해 테스트한다. `.env`를 읽거나 복사하지 않는다.
- 원래 작업 트리에 있던 `AladinApiService`의 `return bookLdist;` 오타는 보존한다. 임시 테스트 사본에서만 HEAD의 `return bookList;`로 바꾼다. 실제 작업 트리 자체의 빌드 통과를 의미하지 않는다.
- 책 모듈 + Modulith 검증: 106개 통과. 이어서 `./gradlew test --no-daemon` 전체 436개 통과(실패/오류/스킵 0).
- 최신 전체 검증: 449개 통과(실패/오류/스킵 0). 모의 HTTP·H2 및 일회성 실제 Redis 사용. MySQL 8 별도 검증으로 컬럼 확장/재실행·긴 소개·참조 보존 확인.
- 데이터 점검 SQL은 의도적으로 만든 잘못된 참조 1건·검토할 ID 1건·좋아요 불일치 1건을 정확히 검출했다. 운영 DB/API에는 접근하지 않았다.

## 병합·배포 전 남은 작업

- 운영 `book.description` 실제 스키마와 ALTER 잠금 시간 확인. 코드/일회성 DB 검증은 완료했다.
- 동일 계정의 모든 인스턴스가 같은 Redis/scope를 쓰는지 확인. 검색 prefetch·검색·상세·추천은 모두 공통 호출 제한을 통과한다. Redis 장애 시 외부 호출을 중단한다.
- 상세 캐시/요청 합치기는 추가하지 않았다. 현재 정확한 호출 제어는 공통 제한기가 담당하며 캐시는 필요량 측정 후 추가한다.
- RN/FE 링크·표지 도메인·빈 페이지 연동 검증.
- 기존 데이터 매칭·참조 보존·백업 및 환경변수 배포 준비, 사용자 미커밋 오타 정리.

클라이언트 연동 및 운영 검증 전에는 배포하지 않는다. 운영 DB 수정·키 등록·배포는 수행하지 않았다.
