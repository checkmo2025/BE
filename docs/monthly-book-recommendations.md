# 분야별 일일 추천 (#311)

## 선정 기준

- 분야 순서: 소설/시/희곡(`001001046`), 인문(`001001019`), 사회 정치(`001001022`), 예술(`001001007`).
- 갱신 시작 시 Asia/Seoul 날짜를 한 번 확정한다. 일자는 선택 순위이며 기준 날짜는 전월 1일이다. 예: 2026-11-05에는 2026-10 월별 순위의 5위를 조회한다.
- `/v1/category/bestsellerMonthly`에 분야·기준 날짜·`page=순위`·`pageSize=1`을 전달한다. 정상 경로는 총 4회 호출하고 4권만 저장한다.
- ISBN 검증은 기존 converter를 사용한다. 같은 날 동일 ISBN은 한 번만 선정한다. 다른 판본 및 과거 날짜와의 중복은 제외하지 않는다.

## 보충과 실패

- 무효 ISBN 또는 이미 선정된 ISBN이면 다음 순위를 조회한다. 끝에 도달하거나 공식 `404/BEST_001`이면 1위부터 탐색한다. 알 수 없는 404와 인증·통신 장애는 후보 부족으로 취급하지 않는다.
- 분야별 후보 조회는 최초 요청을 포함해 최대 5회이며 같은 페이지를 재조회하지 않는다. 요청별 기존 일시적 장애 재시도는 별도로 적용한다.
- 상한은 추가 호출이 무한히 늘어나는 것을 막기 위한 제한이다. 유효한 고유 도서를 4권 확보하지 못하면 부분 저장하지 않고 기존 캐시를 유지한다.
- 정상 요청 4회, 보충 포함 최대 20개 논리 요청이다. 기본 재시도 3회를 포함하면 외부 호출은 갱신당 최대 60회다. 기존 계정 공통 호출 제한도 적용한다.
- 잠금 유효시간은 네 분야 × 후보 상한 × 재시도 횟수 × 요청 최대 대기 예산을 기준으로 계산한다. 기본 설정에서는 2,200초이며, 프로세스가 비정상 종료되면 이 시간이 지난 뒤 잠금이 복구된다. 일반적인 정상 종료·실패에서는 finally에서 즉시 해제한다.

## 캐시와 호환성

- 데이터 키: `book:recommendations:{yes24-monthly-v1}:daily`, 날짜 키: 동일 키의 `:updated_at`, 잠금 키: `:lock`.
- 기존 Lua로 소유권을 확인한 뒤 목록과 날짜를 원자적으로 저장한다. TTL 없이 마지막 성공 결과를 유지한다.
- 구 종합 베스트셀러/알라딘 캐시는 읽지 않는다. 전환 후 최초 생성까지 실패하면 기존 BOOK_500 계약으로 응답한다. 기존 키를 삭제하지 않아 이전 배포로 되돌릴 때 데이터는 보존된다.
- 자정 이후 조회 또는 5분 간격 background 작업에서 날짜 변경을 감지한다. 기존 06:00 KST 예약과 서버 시작 시 점검은 유지한다.
- 전월 데이터 공개 시점·사후 순위 보정·특정 분야의 후보 부족은 공급자에 의존한다. 월 전체 후보를 고정 저장하거나 추천 이력을 추가하지 않는다.
- 외부 추천 응답·검색·상세·좋아요 계약과 DB 스키마는 변경하지 않는다. RN 검색창의 3권 제한은 별도 클라이언트 수정 대상이다.

## 검증 범위

모의 공급자 HTTP부터 실제 추천 서비스와 응답까지 연결해 네 분야 요청 및 한 번의 4권 저장을 검증한다. 날짜/연도/윤년 경계, 중복 보충, 탐색 상한, 부분 실패, 이전 캐시, 요청별 재시도, 잠금 예산을 회귀 테스트한다. 운영 API·운영 Redis·실제 앱 화면 검증은 포함하지 않는다.

참고: https://developers.yes24.com/api-doc/category-bestseller-monthly

최종 검증: `./gradlew test --no-daemon` — 469개 중 465개 통과, 실패/오류 0, 실제 Redis 포트가 필요한 4개는 미실행. 로컬 Docker 데몬이 실행 중이 아니므로 실제 Redis 검증은 별도 환경에서 수행한다. 핵심 구현 변경량은 추가·삭제 합계 114줄이며 새 의존성은 없다.
