# 예스24 전환: 기존 데이터 보존 점검

## 무엇을 옮기는가

외부 공급자만 바뀐다. `book.id`(ISBN), `meeting.book_id`, `book_story.book_id`, `book_liked.book_id`는 변경하지 않는다. 예스24 상품번호로 치환하거나 전체 도서를 재등록하지 않는다. 코드 조사상 현재 참조 테이블은 위 세 곳이며, 과거 `book_recommend`는 기존 마이그레이션에서 제거되었다.

기존 책은 저장 시 DB에서 먼저 재사용한다. 동시에 같은 ISBN을 처음 등록해도 기본키 충돌만 no-op 처리한다. 소개 길이 등 다른 저장 오류는 실패로 전달한다. 예스24 상세가 없거나 장애이면 기존 DB 정보를 사용하며 상품 링크는 null이다.

## 운영 적용 순서

1. 기존 배포 방식으로 DB 백업을 확보하고 복구 가능 여부를 확인한다. 현재 에이전트는 운영 DB에 연결하지 않았다.
2. MySQL 8의 읽기 전용 계정으로 `scripts/yes24/audit-books.sql`을 실행해 전환 전 결과를 보관한다. 명령행 비밀번호 대신 기존 보안 연결 수단을 사용한다.
3. ISBN 검사 이상값은 검토 목록이다. 기존 ISBN-10/내부 ID/비정상 값도 자동 변경·삭제하지 않는다. 기존 참조와 화면을 유지한다. 이 SQL은 예스24 등록 여부를 조회하지 않는다.
4. 정상 스키마에서는 Flyway `V20261014_1__expand_book_description.sql`이 `description`을 LONGTEXT로 확장한다. 이미 LONGTEXT이면 건너뛴다. 점검 SQL에서 컬럼 부재·예상 밖 타입이 나오면 원인을 확인하고 배포를 중단한다. 확장 대상은 char/varchar/tinytext/text/mediumtext이다. ALTER에 필요한 메타데이터 잠금·실행 시간은 운영 크기로 사전 확인한다.
5. 백엔드 환경변수 `YES24_API_KEY`를 비밀 저장소에 등록한다. 같은 계정의 서버는 동일 Redis와 `YES24_ACCOUNT_SCOPE`를 사용한다. 별도 서비스가 같은 계정을 사용하면 이 제한기에 집계되지 않으므로 예산을 별도로 조정해야 한다.
6. 전환 후 같은 점검 SQL을 실행한다. 트래픽이 멈춘 검증 구간에서는 행 수·참조 관계가 같아야 한다. 운영 쓰기가 계속되면 증가분을 구분하고, orphan/좋아요 불일치가 전환 때문에 증가하지 않았는지 확인한다. 집계만으로 모든 행의 동일성을 증명할 수 없으므로 백업/스냅샷 대조를 함께 사용한다.
7. 실제 키로 검색(한글·빈 결과·ISBN 없는 상품), 신규 책 등록, 기존 책의 상세/모임/책이야기/좋아요, 추천 4권 및 공급자 장애 fallback을 확인한다. RN/FE의 null 링크·예스24 이미지 지원을 먼저 반영한다.

## 표지 이미지와 복구

DB에는 이미지 파일이 아니라 URL이 저장되어 있다. 기존 알라딘 표지는 URL을 그대로 보존하므로 해당 호스트의 제공 여부에 의존한다. 이번 작업은 이미지를 재호스팅하거나 전체 표지를 갱신하지 않는다. 추후 표지 이관 시 동일 ISBN의 확인된 정보로만 갱신하고 이전 URL을 복구할 수 있어야 한다.

장애 시 새 배포를 되돌려도 LONGTEXT 컬럼을 VARCHAR(255)로 축소하지 않는다. 축소하면 신규 긴 소개가 유실될 수 있다. 알라딘 서비스 종료 후에는 예전 외부 호출 코드로 롤백해도 서비스 복구를 보장하지 않으므로 기존 DB/추천 캐시 fallback을 우선 확인한다. 실제 키는 소스·문서·Git에 넣지 않는다.

## 로컬 검증 범위

- 전체 449개 테스트 통과: H2 저장·동시 등록, 모의 HTTP, 실제 일회성 Redis, 모듈 경계 검사 포함.
- 일회성 MySQL 8: VARCHAR→LONGTEXT, 이미 확장된 컬럼 재실행, 5,000자 저장, 기존 ISBN·제목·좋아요·FK 참조 보존 확인.
- 실제 운영 컬럼, 운영 데이터 백업/대조, 실서비스 예스24 등록률 및 실제 모바일·웹 화면은 미검증이다.
- 기존 사용자 미커밋 `return bookLdist;` 오타를 제외한 임시 사본에서 테스트했다. 해당 작업 트리의 빌드 성공을 뜻하지 않는다.
